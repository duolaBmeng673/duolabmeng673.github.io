# 光伏优化器最少安装数量：贪心算法总结

## 一、原题描述

有一排固定位置，每个位置要么已经安装了光伏板，要么为空。用数组 `pvs`
表示各位置的状态：

- `pvs[i] = 1`：位置 `i` 已安装光伏板。
- `pvs[i] = 0`：位置 `i` 为空。

优化器只能安装在空位上。安装一个优化器后，它可以覆盖左右相邻位置上的光伏板：只要一块光伏板的左边或右边紧邻位置安装了优化器，这块光伏板就能提升发电效率。

要求计算：**使所有光伏板都被覆盖，最少需要安装多少个优化器。**
如果存在光伏板，其左右相邻位置都无法安装优化器，则返回 `-1`。

输入格式：

1. 第一行是整数 `N`，表示位置数量。
2. 第二行是 `N` 个整数，表示数组 `pvs`。

输出一个整数：最少优化器数量；若无法覆盖所有光伏板，输出 `-1`。

约束条件：

- `1 <= N <= 10^5`
- `pvs` 中每个元素都是 `0` 或 `1`
- 题目保证至少有一块光伏板

### 样例

- `[1, 0]` → `1`：在唯一空位安装优化器，覆盖左侧光伏板。
- `[1, 0, 1, 0, 1]` → `2`：两个空位上的优化器覆盖全部三块光伏板。
- `[1, 0, 0, 1]` → `2`：优化器只能覆盖紧邻光伏板，因此两个空位都需要安装。
- `[1, 1, 1]` → `-1`：没有可安装优化器的空位。

对应第一组样例，ACM 输入输出为：

```text
输入：
2
1 0

输出：
1
```

## 二、主要思路：从左向右贪心

从左到右检查每块光伏板。遇到**尚未被覆盖的光伏板**时，优先尝试在它的**右侧空位**安装优化器；如果右侧不能安装，再尝试左侧空位。如果左右两边都无法安装，就说明无解。

为什么优先选择右侧？

1. 当前光伏板需要被覆盖。
2. 如果右侧为空，在右侧安装优化器可以覆盖当前光伏板。
3. 如果右侧再隔一个位置就是另一块光伏板，那么这个优化器还可以同时覆盖下一块光伏板。
4. 从左向右扫描时，优先把优化器放在右侧，可以尽早兼顾后续的光伏板，避免为相邻的两块板重复安装优化器。

这是一种局部贪心策略：**处理当前未覆盖的光伏板时，优先选择右侧空位，以便在满足当前需求的同时，尽可能覆盖后续光伏板。**

---

### 为什么优先右侧不会错过最优解？

按从左到右的顺序处理，保持一个不变式：**当前下标之前的所有光伏板都已覆盖**。

遇到尚未覆盖的光伏板 `i` 时：

1. 若右侧空位 `i + 1` 可用，任何可行方案都必须在 `i - 1` 或 `i + 1` 安装优化器来覆盖当前板。如果一个最优方案选择左侧，可以把这次安装换到右侧，安装数量不增加。左侧优化器可能覆盖的另一块板是 `i - 2`，它已被此前的选择覆盖；右侧还可能覆盖尚未处理的 `i + 2`，因此交换不会损失后续覆盖能力。
2. 若右侧不能安装，左侧就是覆盖当前板的唯一选择，必须安装或使用已经存在的优化器。
3. 若两侧都不能提供覆盖，当前板不可能被任何更远的优化器覆盖，立即返回 `-1`。

逐步把最优方案调整为这些贪心选择，始终不增加安装数量，因而最终得到最少数量。已被覆盖的板直接跳过，是这个证明和实现的共同前提。

## 三、关键逻辑判断结构

处理位置 `i` 时，可以把判断分成以下几种情况。

### 情况 1：当前位置是空位

```python
if pvs[i] == 0:
    ...
```

当前位置没有光伏板，不需要被覆盖，直接继续向右检查。

### 情况 2：当前位置是光伏板，右侧为空位

```python
if i < n - 1 and pvs[i + 1] == 0:
    ...
```

如果当前光伏板还没有被左侧的优化器覆盖，就优先在右侧安装优化器。这个优化器覆盖当前位置；如果
`i + 2` 也是光伏板，它也会覆盖 `i + 2`。

### 情况 3：右侧不能安装，左侧为空位

```python
if i > 0 and pvs[i - 1] == 0:
    ...
```

如果右侧不是可安装位置，就检查左侧。左侧空位可以安装优化器来覆盖当前光伏板；但如果左侧优化器已经存在，则不能重复计数。

### 情况 4：左右两侧都无法提供覆盖

如果当前是光伏板，而左、右相邻位置都不能安装优化器，也没有已安装的优化器覆盖它，那么问题无解，立即输出
`-1`。

## 四、自己的实现：用指针 `i` 和状态 `pre` 压缩记录

自己的代码没有显式维护 `covered` 和 `has_opt` 两个数组，而是使用：

- `i`：当前扫描位置。
- `count`：已经安装的优化器数量。
- `pre`：扫描过程中的状态标记，用来判断当前光伏板是否已经由前面放置的优化器覆盖。

这里的 `pre`
是对扫描过程的简化记录，并不是在所有情况下都严格表示"物理位置 `i - 1`
上存在优化器"。代码通过移动指针来跳过已经处理过的位置，因此理解时要把
`pre` 和 `i` 的移动方式结合起来看。

### 代码

```python
import sys

def solve():
    input = sys.stdin.readline

    n = int(input())
    pvs = list(map(int, input().split()))
    pvs_len = len(pvs)
    count = 0

    i = 0
    pre = 0  # 扫描过程中的状态标记
    while i < pvs_len:
        if pvs[i] == 0:
            # 当前为空位，不需要覆盖
            pre = 0
            i += 1
            continue

        if i < pvs_len - 1 and pvs[i + 1] == 0:
            # 当前是光伏板，右侧为空，可以优先放置优化器
            if pre == 1:
                # 当前板已被前面放置的优化器覆盖
                i += 1
                continue

            count += 1
            pre = 1
            # 跳过当前光伏板和右侧安装优化器的位置
            i += 2
            continue

        if i > 0 and pvs[i - 1] == 0:
            # 右侧不能安装，尝试使用左侧空位
            if pre == 1:
                # 当前板已被前面放置的优化器覆盖
                i += 1
                pre = 0
                continue
            else:
                # 左侧空位用于覆盖当前板
                i += 1
                count += 1
                pre = 0
                continue

        # 左右相邻位置都无法提供有效覆盖
        print(-1)
        return

    print(count)

if __name__ == "__main__":
    solve()
```

### 如何理解指针跳转

- `i += 1`：当前光伏板或空位处理完毕，继续检查下一个位置。
- `i += 2`：当前光伏板右侧为空，并在该空位安装了优化器；当前板已经处理，右侧空位也无需再作为光伏板检查，因此跨过两个位置。
- `pre = 1`：记录刚刚选择右侧空位安装优化器的状态。
- `pre = 0`：在遇到空位或完成相应的左侧处理后，清除这个局部状态。

这种写法代码较短，但正确性依赖于 `pre`
的含义与每次指针跳转严格配合。若以后修改了跳转顺序，必须重新检查 `pre`
是否仍然代表预期状态。对于更容易解释和维护的实现，可以显式记录覆盖状态。

---

## 五、显式状态实现：显式维护 `covered` 和 `has_opt`

显式实现保留原数组 `pvs`，另外维护两个布尔数组：

- `covered[i]`：位置 `i` 的光伏板是否已经被优化器覆盖。
- `has_opt[i]`：位置 `i` 是否已经安装了优化器。

其中，`pvs`
保存题目给出的原始状态，不被修改。这样就不会把"原本是空位"和"空位上已经安装了优化器"混为一谈。

### 扫描过程

1. 从左向右遍历数组。
2. 如果当前位置不是光伏板，或者当前光伏板已经被覆盖，就跳过。
3. 如果当前光伏板尚未覆盖，优先检查右侧空位：
    -   在右侧安装优化器；
    -   当前光伏板被覆盖；
    -   如果右侧再隔一个位置是光伏板，也将它标记为已覆盖。
4. 如果右侧无法安装，则尝试左侧空位，并同步更新覆盖状态。
5. 如果两侧都无法安装优化器，返回 `-1`。

### 显式状态代码（ACM 输入输出格式）

```python
import sys

def solve():
    input = sys.stdin.readline

    n = int(input())
    pvs = list(map(int, input().split()))

    covered = [False] * n
    has_opt = [False] * n
    ans = 0

    for i in range(n):
        # 空位不需要被覆盖；已覆盖的光伏板也不需要重复处理
        if pvs[i] != 1 or covered[i]:
            continue

        # 优先尝试在右侧空位安装优化器
        if i + 1 < n and pvs[i + 1] == 0 and not has_opt[i + 1]:
            has_opt[i + 1] = True
            ans += 1
            covered[i] = True

            # 该优化器也能覆盖右侧再隔一个位置的光伏板
            if i + 2 < n and pvs[i + 2] == 1:
                covered[i + 2] = True

        # 右侧不能安装时，尝试左侧空位
        elif i - 1 >= 0 and pvs[i - 1] == 0 and not has_opt[i - 1]:
            has_opt[i - 1] = True
            ans += 1
            covered[i] = True

            # 该优化器也能覆盖左侧再隔一个位置的光伏板
            if i - 2 >= 0 and pvs[i - 2] == 1:
                covered[i - 2] = True

        else:
            print(-1)
            return

    print(ans)

if __name__ == "__main__":
    solve()
```

### 两种实现的区别

- **状态记录**：指针版本用 `pre` 压缩局部扫描状态；显式版本用 `covered`、`has_opt` 分别记录覆盖和安装情况。
- **指针移动**：前者结合 `i += 1`、`i += 2` 跳过已经处理的位置；后者固定遍历所有下标。
- **覆盖关系**：前者需要结合状态和跳转推断；后者直接写入 `covered` 数组。
- **可读性**：前者额外空间少，但修改跳转逻辑时要重新检查不变式；后者状态含义直观，便于调试。
- **额外空间**：前者为 `O(1)`，后者为 `O(N)`，都不计输入数组。

## 六、复杂度分析

两种实现都只从左向右扫描数组，每个位置最多被处理常数次。

- **时间复杂度：** `O(N)`
- **显式实现的额外空间复杂度：** `O(N)`，用于 `covered` 和 `has_opt`。
- **自己的实现的额外空间复杂度：** `O(1)`，不计输入数组本身。

由于 `N <= 10^5`，两种实现都满足题目约束。

## 七、总结

这道题的核心不是单纯统计 `1` 的数量，而是处理**相邻覆盖关系**：

1. 遇到尚未覆盖的光伏板时，优先尝试右侧空位。
2. 一个优化器可以同时覆盖左右相邻的两块光伏板。
3. 当前位置被覆盖后，不应重复安装优化器。
4. 如果某块光伏板的左右相邻位置都无法提供优化器覆盖，则返回 `-1`。

自己的实现通过 `pre` 和指针跳转压缩状态，代码更省空间；显式实现通过
`covered` 和 `has_opt`
明确记录覆盖情况和安装情况，可读性更好，也更容易逐步验证。
