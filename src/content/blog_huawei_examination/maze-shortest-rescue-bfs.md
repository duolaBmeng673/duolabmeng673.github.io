# 迷宫最短救援：从 BFS 到状态空间搜索

## 一、题目与通行规则

给定一个 $h$ 行、$w$ 列的二维迷宫，从王子的起点 `S` 出发，求到达公主位置 `P` 的最少移动次数；无法到达时输出 `-1`。每次只能向上、下、左、右移动一格，每次移动的代价都是 1。

| 符号 | 含义 |
|---|---|
| `S` | 起点 |
| `P` | 公主的位置 |
| `.` | 空地 |
| `#` | 墙壁，始终不可进入 |
| `M` | 怪物，无剑时不可进入 |
| `W` | 宝剑，进入后获得宝剑 |

宝剑会改变后续移动的合法性：

- 无剑时，不能进入怪物所在的格子，也不能进入与怪物上下左右相邻的普通格子。
- `W` 是例外：即使紧邻怪物，也可以进入并拾取宝剑。
- 获得宝剑后，可以进入怪物周围的格子，也可以进入怪物格子并击杀它；宝剑不会丢失或消耗，其他怪物仍然存在。
- 起点即使处于危险区域，也允许从那里出发。离开时，目标格子仍须满足通行条件。

输入第一行为 `h w`，接下来 $h$ 行为地图，每行包含 $w$ 个字符。以下实现按合法输入处理，假设地图中恰有一个 `S` 和一个 `P`。在 $h,w\leq 100$ 的规模下，扩展后的状态总数最多为 20000。

## 二、从位置搜索到状态搜索

### 2.1 为什么使用 BFS？

把每个合法状态看作图中的节点，把一次移动看作一条边。所有边的权重都是 1，因此可以使用广度优先搜索。

BFS 的队列按照距离从近到远处理状态：先搜索距离为 0 的起点，再搜索移动一步、两步、三步能够到达的状态。第一次发现某个状态时，其距离已经最短；第一次从队列取出目标状态时，就可以返回答案。

实际搜索对象是一张图。不同路线可能到达同一个状态，因此必须在入队时标记，避免重复扩展。

### 2.2 为什么不能只记录位置？

普通迷宫可以使用 `(x, y)` 表示状态。但本题中，同一位置在“无剑”和“持剑”时允许执行的移动不同。先无剑经过一个格子，之后拿到宝剑再回到这里，可能打开一条新的路线。

因此，完整状态应为：

$$
\boxed{\mathrm{state}=(x,y,\mathrm{sword})}
$$

其中 `sword = 0` 表示尚未获得宝剑，`sword = 1` 表示已经获得宝剑。每个格子最多对应两个状态，状态空间最多包含：

$$
2hw
$$

使用 `dist[x][y][sword]` 同时记录距离与访问情况。初始值为 `-1`，表示尚未发现该状态。仅按位置去重，会错误地丢弃持剑后返回同一格子的路线。

### 2.3 为什么不用记录已击杀怪物？

按本题规则，持剑后已经可以进入所有怪物格子及其相邻格子，而且宝剑不会消耗。因此，某只怪物是否已经被击杀，不会进一步改变持剑状态下的合法移动。

无剑状态下不能击杀怪物，地图危险区域也不会变化。所以只记录 `(x, y, sword)` 就足够，不需要记录怪物存活集合，也不需要在 BFS 中修改地图。

这一结论依赖上述规则。如果宝剑只能使用一次，或击杀怪物后还有其他变化，就需要重新分析状态包含哪些信息。

## 三、预处理危险区域，明确移动条件

### 3.1 危险区域是静态信息

定义二维布尔数组 `danger`，标记与至少一只怪物上下左右相邻的格子。扫描地图找到怪物，再标记每只怪物的四个相邻位置即可，越界位置直接跳过。

墙壁也可能被标记为危险区域，不影响结果，因为移动时会先排除墙壁。

`danger` 只记录危险区域，不能把这些格子永久改成墙：拿到宝剑后，它们就可以通行。

### 3.2 怪物格子和危险区域要分别判断

只检查 `danger[nx][ny]` 并不够。单只怪物所在的格子不一定紧邻其他怪物，因此可能没有被标记为危险区域。

尤其当 `S` 紧邻怪物时，题目允许从危险起点出发，但这不意味着无剑可以走进怪物格子。需要额外检查目标是否为 `M`。

每次尝试移动，按以下顺序判断：

1. 目标是否越界；越界则跳过。
2. 目标是否为墙；墙壁始终不可进入。
3. 无剑时，目标是否为怪物，或是否为不含宝剑的危险格子。
4. 进入 `W` 后更新持剑状态，再检查完整状态是否已经访问。

核心条件为：

```python
if not sword:
    if cell == 'M':
        continue
    if danger[nx][ny] and cell != 'W':
        continue
```

宝剑状态只会从 0 变为 1：

```python
new_sword = int(sword or cell == 'W')
```

起点直接以无剑状态加入队列，不检查它是否危险；后续所有移动都检查目标格子的合法性。

## 四、Python ACM 实现

`deque([(sx, sy, 0)])` 使用包含一个状态的列表初始化队列。这里的 `deque` 是普通的先进先出队列，不是单调队列：从队尾添加状态，从队头取出状态，不维护数值的单调性。

```python
import sys
from collections import deque


def solve():
    input = sys.stdin.readline
    h, w = map(int, input().split())
    grid = [input().strip() for _ in range(h)]
    directions = [(1, 0), (0, 1), (-1, 0), (0, -1)]

    start = None
    princess = None
    monsters = []

    for x in range(h):
        for y in range(w):
            if grid[x][y] == 'S':
                start = (x, y)
            elif grid[x][y] == 'P':
                princess = (x, y)
            elif grid[x][y] == 'M':
                monsters.append((x, y))

    # 标记怪物四邻格子；怪物本身在移动时单独检查。
    danger = [[False] * w for _ in range(h)]
    for x, y in monsters:
        for dx, dy in directions:
            nx, ny = x + dx, y + dy
            if 0 <= nx < h and 0 <= ny < w:
                danger[nx][ny] = True

    # 同一位置的无剑、持剑状态分别记录。
    dist = [[[-1] * 2 for _ in range(w)] for _ in range(h)]
    sx, sy = start
    dist[sx][sy][0] = 0
    queue = deque([(sx, sy, 0)])

    while queue:
        x, y, sword = queue.popleft()

        if (x, y) == princess:
            print(dist[x][y][sword])
            return

        for dx, dy in directions:
            nx, ny = x + dx, y + dy
            if not (0 <= nx < h and 0 <= ny < w):
                continue

            cell = grid[nx][ny]
            if cell == '#':
                continue

            if not sword:
                if cell == 'M':
                    continue
                if danger[nx][ny] and cell != 'W':
                    continue

            new_sword = int(sword or cell == 'W')
            if dist[nx][ny][new_sword] != -1:
                continue

            dist[nx][ny][new_sword] = dist[x][y][sword] + 1
            queue.append((nx, ny, new_sword))

    print(-1)


if __name__ == '__main__':
    solve()
```

## 五、用小地图检查边界

以下示例用于说明规则与检验实现。

### 5.1 宝剑紧邻怪物，仍可拾取

输入：

```text
1 4
SWMP
```

输出：

```text
3
```

`W` 紧邻 `M`，但宝剑格子允许进入。路线为 `S → W → M → P`，获得宝剑后可以穿过怪物并进入其相邻格子。

### 5.2 危险起点可以离开

输入：

```text
2 3
MSP
###
```

输出：

```text
1
```

起点 `S` 紧邻怪物，但右侧 `P` 不在危险区域，因此可以直接走到目标。

### 5.3 允许离开起点，不代表允许进入怪物

输入：

```text
2 3
SMP
#..
```

输出：

```text
-1
```

无剑不能向右进入 `M`，向下又是墙，因此没有合法路线。若只检查怪物的四邻危险区域，就可能错误地允许进入 `M`，再从下方绕行抵达目标。

### 5.4 拿剑后可能需要返回已走过的位置

输入：

```text
2 5
S.MP#
W####
```

输出：

```text
5
```

路线为 `S → W → S → . → M → P`。持剑后返回 `S` 属于新状态，必须允许再次入队；只用二维访问数组会丢失这条路线。

## 六、正确性与复杂度

状态记录了当前位置和持剑情况，足以确定下一步的合法移动。转移依次排除越界、墙壁和无剑状态下禁止进入的格子，并在进入宝剑格子时更新状态，因此搜索只会生成合法路线。

所有移动代价都是 1，BFS 按非递减距离处理状态。第一次发现状态时记录最短距离；再次到达相同状态，其后续可执行的操作没有变化，不需要重复扩展。因此，第一次取出公主所在的状态时得到最短移动次数；队列耗尽仍未找到目标，则说明目标不可达。

最多有 $2hw$ 个状态，每个状态最多入队一次，出队后检查四个方向。地图扫描与危险区域预处理同样只需要线性工作量，所以：

$$
\boxed{\text{时间复杂度 }O(hw),\qquad \text{空间复杂度 }O(hw)}
$$

## 七、可以迁移的状态建模方法

这道题的关键是先判断：**同一个位置，是否会因为之前发生的事件不同，而具有不同的后续选择？**

如果答案是肯定的，就需要把影响后续操作的信息加入状态。例如，钥匙开门、一次性穿墙能力、剩余能量，都可能需要额外的状态维度。但也要检查这些信息是否会影响未来：本题持剑后，怪物是否已经死亡不再影响通行，就不必记录它。

编写搜索前，依次明确三件事：状态包含什么、哪些转移合法、每次转移的代价是多少。单位代价可以使用 BFS；若移动代价不同，就需要根据权重性质考虑 0-1 BFS 或 Dijkstra 等算法。
