# 从三维 DP 到单调队列：CI/CD Pipeline Jobs 最小成本问题

## 1. 题目：恰好执行 t 个任务

CI/CD Pipeline 中有一组按顺序排列的任务。数组 `arr` 的第 `i` 个元素表示任务 `i` 的执行耗时。

从左到右处理任务，每个任务可以选择：

- **执行**：将 `arr[i]` 加入总耗时。
- **跳过**：不增加耗时。

要求连续跳过的任务数量不能超过 `lim`，并且最终必须**恰好执行 `t` 个任务**。求满足条件的最小总耗时；无法满足时返回 `-1`。

数据范围：

```text
0 <= len(arr) <= 1000
1 <= arr[i] <= 10000
0 <= t <= len(arr)
0 <= lim <= 1000
```

> 空数组有一个单独约定：直接返回 `0`。原题示例给出了 `arr = []`、`t = 4` 的情况；虽然它超出了上面 `t <= len(arr)` 的通常范围，仍按这个特殊约定处理。因此代码会先判断空数组，再检查 `t > n`。

连续跳过的限制适用于整个序列，**开头和结尾的跳过也必须计入**，不能只检查两个执行任务之间的间隔。

### 示例 1：无法满足跳过限制

```text
arr = [9, 8, 7, 6, 11, 12, 10]
t = 2
lim = 1
答案：-1
```

执行两个任务后，最多形成三个跳过区间：第一个任务之前、两个任务之间、最后一个任务之后。每个区间最多跳过一个任务，总共只能跳过三个，但这里需要跳过五个。

### 示例 2：最小耗时为 29

```text
arr = [11, 4, 15, 6, 8]
t = 4
lim = 3
答案：29
```

只需要跳过一个任务，跳过耗时最大的 `15` 即可。选择 `11、4、6、8`，总耗时为 `29`，且满足连续跳过限制。

### 示例 3：选择四个低成本任务

```text
arr = [4, 80, 4, 80, 4, 80, 4]
t = 4
lim = 2
答案：16
```

选择下标 `0、2、4、6`，每个中间区间只跳过一个任务。四个任务的耗时都为 `4`，达到执行四个任务的最小可能成本。

## 2. 最自然的状态：三维 DP

同时记录处理进度、执行数量和当前连续跳过数量：

```text
dp[i][j][k]
```

表示处理完前 `i` 个任务，恰好执行 `j` 个任务，末尾连续跳过 `k` 个任务时的最小总耗时。

三个维度分别是：

- `i`：已经处理的任务数量，`0 <= i <= n`。
- `j`：已经执行的任务数量，`0 <= j <= t`。
- `k`：末尾连续跳过的数量，`0 <= k <= lim`。

初始化只有一个可达状态：

```text
dp[0][0][0] = 0
```

其余状态设为 `INF`，表示不可达。处理第 `i` 个任务时，从每个可达状态进行两种转移。

### 执行当前任务

执行数量加一，连续跳过数量清零，成本增加 `arr[i]`：

```text
dp[i + 1][j + 1][0]
    = min(dp[i + 1][j + 1][0], dp[i][j][k] + arr[i])
```

这个转移要求 `j < t`。不论之前连续跳过多少个任务，执行当前任务后都会回到 `k = 0`。

### 跳过当前任务

执行数量不变，连续跳过数量加一，成本不变：

```text
dp[i + 1][j][k + 1]
    = min(dp[i + 1][j][k + 1], dp[i][j][k])
```

这个转移要求 `k < lim`，否则再跳过一个就会违反限制。

### 最终答案

处理完全部任务后，只要求执行数量为 `t`，末尾连续跳过多少个都可以，只要没有超过 `lim`：

```text
answer = min(dp[n][t][k] for k in range(lim + 1))
```

若所有这些状态都不可达，返回 `-1`。

## 3. 正确，但时间复杂度过大，有优化空间

直接枚举三个维度，时间和完整 DP 表的空间复杂度都是：

```text
O(n × t × lim)
```
时间复杂度过高，且内存占用可能达到 `1000 × 1000 × 1000 = 10^9`，无法在常规环境下运行。
考虑是否有优化方法？
官方题解给出可以将连续跳过的限制转化为相邻执行位置的间距约束，从而把三维 DP 降为二维 DP，再用单调队列维护滑动窗口最小值。

## 4. 把连续跳过转换成位置间距

使用从 `0` 开始的下标。假设最终执行的位置为：

```text
p1 < p2 < ... < pt
```

连续跳过的任务被分成三个部分：

```text
第一个执行位置之前：       p1
相邻执行位置之间：         p(j + 1) - pj - 1
最后一个执行位置之后：     n - 1 - pt
```

它们都必须不超过 `lim`，因此约束等价于：

```text
p1 <= lim
p(j + 1) - pj <= lim + 1
n - 1 - pt <= lim
```

中间的限制是 `lim + 1`，因为两个执行位置之间真正跳过的数量是**下标差减一**。

例如选择下标 `0` 和 `3`，中间跳过的是下标 `1、2`，共`2 = 3 - 0 - 1`个任务。当 `lim = 2` 时，这个间距是合法的。

### 提前判断是否有解

执行 `t` 个任务，需要跳过 `n - t` 个任务。跳过任务可以分布在 `t + 1` 个区间，每个区间最多容纳 `lim` 个：

```text
n - t <= (t + 1) × lim
```

这是必要条件，也是充分条件：只要总容量足够，就能把 `n - t` 个跳过任务分配到这些区间，再在区间之间放置 `t` 个执行任务。

这个判断只回答**是否存在合法选择**，不能决定哪组任务的成本最小。

边界也可以直接理解：

- `t = 0`：只能跳过全部任务，如果 `n <= lim` 返回 `0`，反之返回 `-1`。
- `lim = 0`：任何任务都不能跳过，因此必须 `t = n`。
- `t = n`：全部执行，总耗时为 `sum(arr)`。

## 5. 改用“最后一次执行的位置”作为状态

定义 `cost[j][i]`：恰好执行 `j` 个任务，且最后一个执行任务位于下标 `i` 时的最小成本。

这个状态描述的是**截至最后一次执行的位置**，还没有处理它之后的任务。因此后缀跳过限制需要在取最终答案时单独检查。

### 第一层：只执行一个任务

首个执行位置之前最多跳过 `lim` 个任务：

```text
cost[1][i] = arr[i]    if i <= lim
cost[1][i] = INF       otherwise
```

### 后续层：寻找合法的前一个执行位置

当前执行位置为 `i`，上一个执行位置为 `k`，必须满足：

```text
i - lim - 1 <= k <= i - 1
```

于是：

$$
dp[j][i] = arr[i] + \min_{k\in[i-lim-1,\ i-1]} dp[j-1][k]
$$

最后执行任务为 i，因此 i 任务一定执行，根据动态规划局部最优解，一定是 arr[i] + 上一层的最小值。         
注意最小值来自**上一层 `j - 1`**，不是当前层。实现时使用 `previous` 和 `current` 两个数组，防止同一层的结果被错误地再次使用。

### 最后一层：检查后缀

恰好执行 `t` 个任务后，最后执行位置 `i` 还必须满足：

```text
n - 1 - i <= lim
```

即最终答案只在以下范围内取最小值：

```text
max(0, n - 1 - lim) <= i <= n - 1
```

如果忽略这一步，就可能得到末尾连续跳过过多任务的非法答案。

## 6. 新的瓶颈：滑动窗口最小值

状态已经变成二维，但如果每次计算 `cost[j][i]` 都重新扫描上一层的合法区间，每个位置仍需检查最多 `lim + 1` 个候选，这与三维 dp 数组的时间复杂度无异：

```python
best = INF
for k in range(max(0, i - lim - 1), i):
    best = min(best, previous[k])
```

总时间仍为 `O(n × t × lim)`。
考虑到当前层状态 `current[i]` 的计算依赖上一层 `previous` 在一个连续区间内的最小值，我们可以进一步优化这个最小值的求解过程。

由状态转移可知：
$$
dp[j][i] = arr[i] + \min_{k\in[i-lim-1,\ i-1]} dp[j-1][k]
$$

当 `i` 从左向右移动一位时，参与取最小值的候选区间也会同步向右移动一位。此时，窗口右侧只会新增一个候选位置 `i - 1`，左侧则会有过期位置被移出。

因此，这个区间最小值实际上构成了一个**滑动窗口最小值**问题。与其对每个 `i` 重新遍历整个候选区间，不如维护一个能够动态更新窗口最小值的数据结构，从而进一步降低状态转移的时间复杂度。

## 7. 从滑动窗口到单调队列

既然每次状态转移需要求一个滑动窗口中的最小值，那么一个自然的想法是：**能不能在窗口移动的过程中，只保留那些真正有可能成为最小值的候选？**

例如，当前窗口中的候选成本依次为：

```text
3、5、7
```

如果此时窗口右侧加入一个新的候选，成本为 `4`，那么 `7` 和 `5` 还有继续保留的必要吗？

答案是否定的。

新候选 `4` 的成本比它们更低，而且它的位置更靠右，因此它会比 `5` 和 `7` 更晚离开滑动窗口。也就是说，只要 `5` 或 `7` 未来仍然处于窗口中，`4` 就一定也处于窗口中，并且成本更低。因此，`5` 和 `7` 从此不可能再成为窗口最优解，可以直接删除。

加入 `4` 后，候选就从：

```text
3、5、7
```

变成：

```text
3、4
```

这启发我们：**窗口中并不需要保存所有候选，只需要保存那些仍然有可能成为未来最小值的候选。**

进一步观察，如果按照候选的下标顺序保存这些元素，那么：

- 下标天然是从左到右递增的，可以用来判断哪些候选已经离开窗口；
- 对于仍然有竞争力的候选，其成本也应该保持递增，这样队首就始终是当前窗口的最小值。

于是，我们可以使用一个双端队列，同时维护这两个性质：

1. **下标递增**：用于判断候选是否过期；
2. **`previous[index]` 递增**：用于保证队首始终是窗口最小值。

每当一个新候选加入时，从队尾删除所有成本大于或等于它的旧候选；每当窗口向右移动时，从队首删除已经过期的候选。

这样，我们就得到了**单调队列维护滑动窗口最小值**的方法。

特别地，当两个候选成本相同时，也删除旧候选。因为新候选的位置更靠右，成本相同但能够在窗口中存活更久，因此旧候选已经没有保留价值。

### 每个位置的四个步骤

计算当前下标 `i` 时：

1. 删除队首中小于 `i - lim - 1` 的过期下标。
2. 将新候选 `i - 1` 加入队列，但跳过不可达 `INF` 状态。
3. 加入前，从队尾删除成本大于或等于新候选的下标。
4. 若队列非空，用队首成本加上 `arr[i]` 得到当前状态。

队列保存下标，而不是只保存成本，是因为成本本身无法告诉我们一个候选是否已经离开窗口。

### 为什么嵌套 while 仍然是线性的？

一层 DP 中，每个下标最多入队一次，也最多被移除一次：可能从队尾因成本劣势被删除，也可能从队首因过期被删除。

虽然某一次循环会删除多个候选，但整层的删除总次数不超过 `n`。因此一层是 `O(n)`，而不是 `O(n²)`。

## 8. 最终 Python 实现

下面保留函数形式，因为给出的题目没有规定标准输入格式。`collections.deque` 是 Python 标准库，不需要额外依赖。

```python
from collections import deque


def min_cost(arr, t, lim):
    n = len(arr)

    # 按题目特殊约定，空任务队列直接返回 0。
    if n == 0:
        return 0
    if t > n:
        return -1
    if t == 0:
        return 0 if n <= lim else -1

    # t 个执行任务将跳过任务分隔为 t + 1 个区间。
    if n - t > (t + 1) * lim:
        return -1
    if t == n:
        return sum(arr)

    INF = 10**18

    # previous[i]：执行上一层数量的任务，最后执行位置为 i。
    previous = [INF] * n
    for i in range(min(n, lim + 1)):
        previous[i] = arr[i]

    for selected_count in range(2, t + 1):
        current = [INF] * n
        candidates = deque()

        for i in range(n):
            # 合法的上一个位置范围为 [i - lim - 1, i - 1]。
            window_left = i - lim - 1
            while candidates and candidates[0] < window_left:
                candidates.popleft()

            k = i - 1
            if k >= 0 and previous[k] != INF:
                # 新候选更便宜，或同样便宜但更晚过期。
                while candidates and previous[candidates[-1]] >= previous[k]:
                    candidates.pop()
                candidates.append(k)

            if candidates:
                best_previous = candidates[0]
                current[i] = previous[best_previous] + arr[i]

        previous = current

    # 末尾跳过数量也不能超过 lim。
    first_valid_last = max(0, n - 1 - lim)
    answer = min(previous[first_valid_last:])
    return -1 if answer == INF else answer
```

`INF = 10**18` 足够大：题目范围内，执行所有任务的总成本最多是 `1000 × 10000 = 10^7`。代码不把不可达状态加入候选队列，避免对 `INF` 继续进行成本转移。

`selected_count` 表示当前层恰好执行多少个任务。虽然它不直接出现在成本计算中，但循环层数保证最终数组对应的是执行 `t` 个任务，而不是至多 `t` 个。

### 样例与边界检查

```python
assert min_cost([9, 8, 7, 6, 11, 12, 10], 2, 1) == -1
assert min_cost([11, 4, 15, 6, 8], 4, 3) == 29
assert min_cost([4, 80, 4, 80, 4, 80, 4], 4, 2) == 16
assert min_cost([], 4, 0) == 0

assert min_cost([2, 5, 3], 0, 3) == 0
assert min_cost([2, 5, 3], 0, 2) == -1
assert min_cost([2, 5, 3], 3, 0) == 10
assert min_cost([2, 5, 3], 2, 0) == -1

# 只执行一个任务时，前缀和后缀都必须合法。
assert min_cost([1, 100, 100, 100, 1], 1, 2) == 100
```

最后一例中，首尾两个耗时为 `1` 的任务都不能单独选择，因为另一侧会连续跳过四个任务。唯一合法的执行位置是中间的下标 `2`。

## 9. 正确性与复杂度

第一层准确覆盖所有合法的首个执行位置。之后每一层只从上一层的合法位置窗口转移：增加一个执行任务，且中间跳过不超过 `lim`。因此不会产生非法前缀。

反过来，任何合法方案的倒数第二个执行位置，都必定落在最后执行位置对应的窗口内。转移枚举了所有这样的候选，并通过单调队列取到其中的最小成本，所以不会遗漏最优方案。

最后对执行 `t` 个任务的状态施加后缀限制，便得到整个序列的最优合法答案。

优化后的一般情况（`t >= 1`）：

```text
时间：O(n × t)
空间：O(n)
```

每层使用两个长度为 `n` 的数组以及一个最多包含 `n` 个下标的队列。原始三维 DP 的 `k` 维被位置窗口约束替代，窗口扫描又被均摊线性的队列维护替代。

## 10. 从这道题提炼出的思路

整个优化过程可以归纳为：

```text
执行 / 跳过
    → 三维 DP：处理进度、执行数量、连续跳过数量
    → 观察跳过区间：约束相邻执行位置的距离
    → 二维 DP：执行数量、最后执行位置
    → 转移需要滑动窗口最小值
    → 单调队列维护候选，滚动数组保存上一层
    → O(n × t) 时间、O(n) 空间
```

遇到一个正确但太慢的 DP，不必急着套优化模板。先写清楚状态含义和边界，再检查转移中是否存在反复求解的区间问题。单调队列不是这道题的起点，而是观察转移结构后得到的结果。
