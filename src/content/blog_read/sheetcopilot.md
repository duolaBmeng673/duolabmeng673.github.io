# SheetCopilot

# Abstract \& Introduction:

SheetCopilot旨在实现“自然语言控制excel处理”。为此，编者为LLM专门设计了221个电子表格控制任务的代表性数据集，并建立全自动的评估系统，以严格基准测试测试LLM在软件控制任务中的能力。

如今，将LLM和软件应用结合面临许多挑战

1. 一方面，缺乏模型\-应用交互的标准化框架和评估模型性能的综合基准。

2. 一方面，设计LLM和复杂应用程序交互的框架也存在诸多困难：1、将应用复杂的内部状态和应用庞大功能转化为模型可理解的文本形式，我们需要确定如何通过自然语言系统地表示软件接口和逻辑；2、使模型能够准确和安全的生成软件命令和参数，必须存在验证和调试机制并可以拒绝和修改模型输出；3、提供模型软件状态变化、异常和错误的监控以便其做出适当反应；此外，还需要适当处理数据集以适应现实语言的多样性和模糊性

该论文以电子表格处理为目标，设计了SheetCopilot代理和专用数据集，SheetCopilot可以理解自然语言对Excel处理的请求并将复杂请求分解为逐步计划；数据集包含自然语言表达的复杂交互式电子表格操作请求和自动化指标的评估框架。SheetCopilot对基准测试中的87\.3%的问题生成了可执行命令，并为44\.3%的任务生成正确的解决方案。

综上，该论文有以下贡献：

1. 提出SheetCopilot代理用于将自然语言命令转化为可执行命令序列

2. 开发完整、自动且可靠的测试和评估体系

3. 对领先LLM进行深入评估，并且配置论文方法方法的LLM表现明显优于强大的代码生成基线模型

# Related Works

## Tool\-augmented Large Language Models 工具增强的大语言模型:

近期的研究探索了如何通过大语言模型完成任务规划，部分研究利用外部工具（如浏览器、化学软件等）增强模型功能，但很少有研究专门评估LLM在控制电子表格方面的能力。

## Natural Language Processing\(NLP\) for Spreadsheets 自然语言处理在电子表格中的应用:

已有研究使用NLP技术进行电子表格操作，比如Flash Fill和NLyze，它们可以将自然语言指令转化为可执行程序。最近的研究也表明LLMs如GPT\-3和T5能有效生成Excel公式，但主要聚焦在公式生成上，而不是其他电子表格操作。

# Dataset and Evaluation

## Diverse Seed Task and Workbench Collection

首先，从Superuser网站抓取问题，利用LLM关键词筛选至13k个Q\&A对，然后进行数据集分类，最后对每个类别进行嵌入和聚类并选出聚类中心的67个Q\&A对；测试集方面，采用网上下载和手动制作的方式，组成了28个真实世界中常见用途的Excel

## Core Set Collection

**Adaptation：**（个人理解）将3\.1中筛选得到的种子任务和评估表的详细描述提供给LLM，LLM被提示根据后者生成新的更加详细的任务以能够与评估表兼容

**Simplification：**提醒LLM将每个任务中的特定专业公式和操作代替为自然语言

最后，笔者收集更多的任务来丰富核心数据集，最后得到221个任务构成的数据集。

## Core Set Collection

为确保评估的有效性和准确性同时保证工作量不会爆炸，作者提出了一种方法，即评估执行解决方案后生成的最终表格状态是否满足任务指令的要求。评估时仅关注任务所需的必要属性，忽略其他细节。

# Method

题者受GPT\-3启发，提出了表示常见电子表格函数的虚拟API，名为"atomic actions"，这允许语言模型准确地与电子表格软件进行交互。

## Prompting LMs as a SheetCopilot

题者设计了系统提示模板，将LMs转化为copilots助手，prompt包含以下成分：一般作用描述；带有参数的原子动作列表；一组输出要求以及用户和助手之间的多轮交互示例

![1737166616239\_d\.png](/articles/sheetcopilot/1737166616239_d.png)

一般作用描述是LMs理解上下文的锚点；原子动作列表为LMs提供了任务规划所需的接口信息；输出要求告诉LMs如何生成可以编程提取和执行的文本

## Atomic Action as A Bridge for LMs and Software

为能将LLM生成的自然语言计划转化为机器可执行命令，提出将电子表格软件功能建模为一组成为原子动作“atomic actions”的虚拟API，原子动作由API名称，参数列表，文档字符串和用法示例组成，这些原子动作可以在各个电子表格平台上实现。

原子动作必须是可表达的并且简洁以适应LMs窗口，题者决定按如下顺序确定原子动作：1、提取顶层SuperUser电子表格Q\&A的所有行动；2、将提取的行动嵌入和集成到候选中；3、选取覆盖我们在3\.1节中收集的所有任务的做小动作集

## State Machine\-based Task Planning

题者提出一种基于状态机的规划器，能够根据LMs和软件的反馈修改计划，规划器分为观察\(Observing\)、提出\(Proposing\)、修改\(Revising\)和执行\(Acing\)阶段。

### Observing Stage:

将表格状态St的简要描述添加到查询query中，提供表格行列参数等重要信息。

## Proposing Stage:

此阶段将系统提示P，初始任务指令I，表状态St和规划历史Ht连接起来，并要求LMs计划下一个原子动作A\(t\+1\)

![1737168378760\_d\.png](/articles/sheetcopilot/1737168378760_d.png)

### Revising Stage:

如果模型的提议存在问题（如生成了无效的操作），则进行修正。修正可以通过反馈或检索外部文档来改进模型的生成

### Acting Stage:

将修正后的操作提交给电子表格软件执行，更新表格状态。

## Hallucination Mitigation

该节讨论了模型生成无效或不符合预期的操作

### Output Formatting：

LLMs生成的操作计划虽然语义正确，但可能格式不符合要求，导致无法执行。为此，论文要求模型将操作用特定标记（例如@符号）包裹，确保输出符合格式要求，从而减少格式错误。

### Atomic Action Disambiguation：

LLMs可能会将内在知识与电子表格操作的定义混淆，导致产生未定义的操作或错误的操作参数。这种现象被称为“幻觉”。为了缓解这一问题，论文提出用与官方操作名不同的同义词来替换原子操作的名称，从而避免模型自我欺骗并产生无效操作。
