## 一、整体骨架

| 层级 | 规范 |
| --- | --- |
| 交付形式 | 一整块 markdown 代码块 |
| H1 | 主题名 + 括号内的核心算法名 |
| H2 | 数字编号，章与章之间用 `---` 分隔 |
| H3 | 每个概念一节，细分用 H4 |
| 顺序 | 概览 → 概念；**涉及计算的主题**再加：做题步骤 → 例题 |

概览只回答四件事：它是什么、怎么构建、什么时候停止、**核心问题**是什么。

## 二、概念部分的写法

1. **先放完整例题数据**：概念部分一开头就摆出数据表，所有概念都在这份数据上举例，沿用同一个例子。
2. **先符号，后公式**：先给"符号 | 含义"表（关键词加粗），再给一张实例化表，把符号落到具体数据上；计算约定放进引用块。
3. **每个概念块的固定模板**：
   - 标题 = 圈号 + 名称 + 符号（**不再加大白话问句**）
   - 独立公式
   - 加粗标签的要点：**算法** / **意义**（需要时加 **缺点**）
   - 在例题数据上的具体计算
4. **公式里每个符号都要解释**：写在公式正下方，用大白话说明下标、求和号、分母各自是什么，用例子代入，再加一句"如果是三类就多一项"这样的延伸。
5. **易混概念放对比表**：紧跟在相关概念后面，列"数的是什么 | 例子"，再补两条要点说明区别。
6. **圈号 ①–⑤ 当固定标签**：步骤、计算表、交叉引用都用同一套。
7. **不写 PPT 叫法，也不标 PPT 页码**。

## 三、仅涉及计算题的规范

**做题步骤与例题**

- 概念之后单独一节做题步骤，编号列表，关键词加粗，引用圈号。
- 例题开头用加粗的 **题目** 一行。
- 数据表**完整给出，不简写**。
- 步骤 1 是数个数表（取值 | 样本数 | 各类个数 | 样本编号），步骤 2 是计算表（量 | 计算 | 结果）。

**计算书写**

- 公式 → 代入 → 结果，三步都写，零项也写出来（如 $0/2$ 的形式）。
- 至少拆开一个子项逐项写，如 $0.5288+0.4422$。
- 计算格里用括号补一句说明。
- 先完整算一个属性，其余写"同理"并给汇总表。
- 同一例题内小数位统一；结果加粗；被选中的行加粗并标"← 最大"；决定用一句加粗的话写出。

**表格**

- 个数写成"类别一/类别二"，表前先说明。
- 紧凑格式：`取值 样本数（a/b）· 取值 样本数（a/b）`。
- 分组表里重复的第一列留空，数值列可右对齐。

## 四、可选内容

逐层递归的分步演示（每层一个 H3、子数据集保留原编号、说明已排除的属性）、最终结果树和 if-then 规则列表，**只在主题需要时写，可有可无**。

## 五、SVG 设计规范（重点）

| 雷点 | 要求 |
| --- | --- |
| 文字与图案重合 | 文字不压在形状边线、连线或其他文字上；框内文字要留足边距，标签与连线错开 |
| 颜色单一 | 不要通篇只用一两种颜色；按角色分配多色配色，同一角色颜色保持一致 |
| 越界 | 所有元素都在 viewBox 内并留出边距；文字不超出所在框，边缘不被裁切 |

**HTML 演示**只在复杂算法时才做（点击逐步演示），简单主题不需要。

## 六、语言与排版

- 数学用 LaTeX。
- 中文短句，关键术语加粗。
- 表情符号只在你自己加时出现，**不用 🟨**。

## 七、刻意不写的内容

勘误 / PPT 错误总结、速记 / 自测题、额外的算法变体（除非你要）、PPT 里的习题和 tips 页。

## 八、与以往笔记共通

- 笔记以基本概念、运作方式、核心作用为主。
- 配图习惯：SVG 图示，必要时拆成独立 SVG 文件。
- 例题数据沿用 PPT 的原例；每个表或结构用一句话说明作用。
