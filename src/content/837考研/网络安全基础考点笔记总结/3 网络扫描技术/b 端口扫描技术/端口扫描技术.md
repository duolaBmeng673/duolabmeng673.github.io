# 端口扫描

## 一、基本概念

**端口扫描**：向目标主机发送**探测数据包**，根据**是否收到响应**判断端口状态，探测目标主机上开放了哪些服务。

## 二、扫描类型

| 类型 | 方法 | 判断依据 | 特点 |
|---|---|---|---|
| **TCP 全连接扫描** | 通过系统 `connect()` 完成完整三次握手 | 成功=开放；拒绝=关闭 | 稳定可靠；**不隐蔽**、慢、会被日志记录 |
| **TCP SYN 扫描**（半连接） | 只发 SYN，不完成握手 | `SYN+ACK`=开放（再发 `RST` 终止连接，避免被记录）；`RST`=关闭 | **隐蔽**、快；需要权限 |
| **FIN 扫描** | 发送 FIN 包 | 无回复=开放；`RST`=关闭 | 隐蔽 |
| **NULL 扫描** | 所有 TCP 标志位为 0 | 无回复=开放；`RST`=关闭 | 隐蔽；Xmas 的变种 |
| **Xmas 扫描** | `FIN`/`URG`/`PSH` 标志位置 1 | 无回复=开放；`RST`=关闭 | 隐蔽；依赖 UNIX 协议栈行为 |
| **UDP 扫描** | 发送 UDP 包 | `ICMP_PORT_UNREACH`=关闭；无响应=可能开放 | 不可靠、慢、易被过滤 |
| **FTP 扫描** | 使用 `PORT` / `LIST` 命令 | 根据 FTP 服务器的返回判断 | — |

## 三、FIN / NULL / Xmas 扫描的原理

- 这三种都是向目标发送**异常 TCP 包**，利用目标对异常行为的处理差异判断端口状态：
  - **端口开放**（有进程监听）：对异常包**不做回应**。
  - **端口关闭**：回复 `RST`。
- **无回应说明有进程在监听端口**。
- **只适用于 UNIX 系统主机**：**Windows 无论端口是否开放，一律直接回复 `RST`**，无法据此判断。
