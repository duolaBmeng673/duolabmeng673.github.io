# 网络数据包的捕获

## 网卡的工作原理

### 一、工作层次与地址

- 网卡工作在**数据链路层**，用 **MAC 地址**标识自己。
- MAC 地址长 **6 字节（48 bit）**：前 3 字节分配给厂商，后 3 字节由厂商自行分配。
- 查看方式：`ipconfig`（Windows）。

### 二、数据帧结构

- 帧头包含**源 MAC** 和**目的 MAC**。
- 网卡从链路上读入数据帧，根据**目的 MAC** 决定是否接收。

### 三、网卡的四种接收模式 

| 模式 | 接收内容 |
|---|---|
| **单播** | 仅接收目的 MAC 为本网卡的帧（**默认**） |
| **广播** | 接收广播帧，目的 MAC 为 `FF-FF-FF-FF-FF-FF`（全 1） |
| **组播** | 接收所加入的组播组的帧 |
| **混杂** | **不过滤，一切帧都接收** |

### 四、不同模式下的处理流程 

**1. 非混杂模式**
- 网卡检查目的 MAC → 目的 MAC 是**自己**或**广播地址** → 产生**硬件中断**（CPU 执行），把帧交给**协议栈**处理。
- 否则 → **直接丢弃**。

**2. 混杂模式**
- 网卡**不做地址过滤**。
- **所有帧**都产生硬件中断，交给系统协议栈处理。
- 处于混杂模式的机器即成为 **sniffer**。

**3. 驱动接收流程**
- 操作系统根据网卡驱动中设置的**中断程序地址**调用驱动程序接收数据，放入**信号堆栈**，交给操作系统处理。

```text
帧到达网卡 → 硬件中断 → 驱动程序 → 信号堆栈 → 协议栈
```

### 五、DMA 机制

**DMA（Direct Memory Access，直接内存存取）**：允许外围设备（网卡、磁盘控制器、显卡、声卡等）**直接访问系统主内存**，数据传输**绕开 CPU 的全程调度**。

**1. 工作方式**
- 传输过程由 **DMA 控制器**控制。
- CPU 只在传输**开始和结束**时做少量处理（中断处理），传输过程中可继续做其他工作。
- CPU 计算与 I/O 操作**并行**。

**2. 核心作用**
- 数据仍需从网卡拷贝到主存，但**拷贝过程 CPU 不参与**，不消耗 CPU 资源。
- 避免了这一层 data copy 的 CPU 损耗，**提高整个系统的效率**。


## Sniffer 嗅探

### 一、基本概念 

**Sniffer（嗅探）**：将网卡设置为**混杂模式**，捕获整个网络的数据流量并**过滤**，把感兴趣的信息交给上层处理。
- 工作在网络环境的**底层**，拦截网络上正在传送的数据，**实时分析**数据内容。

### 二、共享环境下

- Sniffer 可**直接捕获整个网段**的通信。
- 网卡设为**混杂模式**，接收目的地址不是自身的帧，直接访问**数据链路层**获取数据，再交给上层过滤处理。
- 可使用 **libpcap / winpcap** 等。

### 三、交换式网络环境下 

交换机只向目的端口转发，无法监听其他端口和其他网段的数据，所以 Sniffer 必须**结合其他技术**，常用方法有：

1. 将捕获程序放在**网关**上。
2. **端口映射、端口盗用**。
3. 在交换机与路由器之间连接 **hub**。
4. **ARP 欺骗**：伪造 ARP 应答，让其他主机把帧发给攻击者。
5. **MAC 地址欺骗**：伪造源 MAC，改写交换机 MAC 表。
   - 也可采用 **MAC 泛洪（MAC Flooding）**：填满转发表，交换机无处可查只能**广播**，被攻击成**集线器**。


## Sniffer 防范

### 一、防范方法

| 方法 | 做法 | 作用 |
|---|---|---|
| **检测嗅探器** | 检测网络中处于**混杂模式**的网卡 | 发现攻击者，**不阻止捕获** |
| **安全拓扑** | 网络划分越细，能采集的信息越少（如 **VLAN**） | **缩小被捕获的范围** |
| **地址绑定** | 见下方 | 阻止流量流向攻击者 |
| **会话加密** | 加密后传输（**HTTPS / SSL / IPsec**） | 抓到也是密文，**最好最常用** |

### 二、地址绑定

- **交换机端口与 MAC 绑定**：防止**端口盗用、MAC 攻击**。
- **路由器 IP 与 MAC 静态绑定**：用**静态 ARP** 代替动态 ARP，防止 **ARP 欺骗**。
