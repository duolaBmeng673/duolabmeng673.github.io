# 包捕获机制

## BPF 模型

### 一、基本概念 

**BPF（Berkeley Packet Filter，伯克利包过滤器）**：工作在**操作系统内核层**，在内核里先过滤，只把需要的包交给用户进程，减少内核态到用户态的拷贝开销。

- 包捕获机制是在**数据链路层增加一个旁路**，把数据包看成**字节数组**，进行**谓词过滤**。
- **旁路**：原包照常走协议栈，在驱动处**额外分出一条支路**，把**副本**送去 BPF，不影响原包。

### 二、三层结构

| 层次 | 内容 |
|---|---|
| **最底层** | 针对操作系统的包捕获机制 |
| **中间层** | 包过滤机制 |
| **最高层** | 针对用户程序的接口（如 libpcap） |

### 三、BPF 的组成 

- **网络分接头**：负责**收集、复制**网络数据包。
- **数据过滤器（核心）**：根据**用户规则**决定是否接收数据包，通常用于实现 **sniffer**。

### 四、工作流程 

1. 网卡驱动接收数据包后，正常**交给协议栈**。
2. 若有进程用 BPF 侦听，驱动先调用 BPF **复制一份**。
3. **过滤器**根据用户规则判断是否接收：
   - **接收**：复制到**内核缓冲区**暂存，收集足够数据后**一起提交**给用户进程（如 libpcap），以提升效率。
   - **不接收**：丢弃副本。
4. 发往本机的包，**仍交给系统协议栈**处理。

```text
网卡驱动收到包
   ├─ 主路：协议栈 → socket → 应用（照常）
   └─ 旁路：复制一份 → BPF 过滤 → 内核缓冲区 → libpcap → 抓包程序
```
