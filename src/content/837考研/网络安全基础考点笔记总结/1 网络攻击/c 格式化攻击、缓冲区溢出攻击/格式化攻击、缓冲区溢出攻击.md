# 格式化攻击、缓冲区溢出攻击

## 格式化字符串攻击

### 一、定义 🟨

**格式化字符串攻击（Format String Attack）**：利用程序对**格式化函数**使用不当的漏洞，当**用户可控的数据被直接当作格式串**时，攻击者通过构造特殊的格式符，**读取或改写内存**，从而泄露信息、使程序崩溃，甚至执行任意代码。

### 二、以 printf 为例 

**1. 格式串与 printf 原理**
- **格式串**：`printf` 的第一个参数，由普通字符和以 `%` 开头的**格式符**（`%d`、`%s`、`%x`、`%n` 等）组成。
- `printf` 是**变参函数**，自己不知道实际传了几个参数。它按格式串中的格式符，依次从**栈**上取参数、转换并输出。

```c
printf("%s 今年 %d 岁\n", name, age);   // 格式符与参数一一对应
```

**2. 漏洞成因** 🟨

- 正确写法（格式串固定，buf 只是数据）：
```c
printf("%s", buf);
```
- 有漏洞的写法（用户输入 buf 直接当作格式串）：
```c
printf(buf);
```
- 若用户输入 `%x%x%x`，格式串中有 3 个格式符，却没有传入对应参数，`printf` 不会报错，而是**从栈上取出不属于它的数据**并打印，造成栈内容泄露。

**3. 为什么没传参数也会取到值** 

① **参数通过栈传递**：调用函数时，参数被依次压入栈中，`printf` 内部维护一个"参数指针"，初始指向格式串之后的位置。

② **printf 不知道实际传了几个参数**：它是变参函数，唯一的线索是格式串。**每遇到一个格式符，就从参数指针处取一个值，然后指针移到下一格**。

③ **它不会检查"参数是否真的存在"**：格式符的个数与实际参数个数是否一致，`printf` 不校验。

![格式化字符串攻击栈参数示意图](<./format_string_attack_stack_compare.svg>)

- 格式串地址之后的这些位置**并不是调用者传入的参数**，而是栈上原本就有的数据（调用者的局部变量、保存的寄存器、返回地址等）。
- `printf` 按格式符照常去取，并把它们**当作参数以十六进制打印出来**，于是栈中内容被泄露。

**4. 本质**

- 正常情况：用户输入处于"**数据**"位置，其中的 `%` 只是普通字符。
- 漏洞情况：用户输入处于"**格式串**"位置，其中的 `%` 被当作**指令**执行。
- 即：**程序把用户输入当成了格式串，用户因此获得了控制 printf 行为的能力**。

**. 攻击过程示例**

```c
char buf[100];
gets(buf);
printf(buf);
```
- 输入 `AAAA%x.%x.%x.%x`：输出栈上若干值，若出现 `41414141`，说明输入本身位于栈上，可用来构造任意地址；
- 输入 `AAAA%4$s`：把栈上第 4 个参数（即 `AAAA`，地址 0x41414141）当作地址，读取该处字符串；
- 输入 `<目标地址>%100c%4$n`：向目标地址写入 100。

### 三、防御

1. **固定格式串**：始终写成 `printf("%s", buf)`，不让用户输入充当格式串；
2. 对用户输入过滤 `%` 等格式符；
3. 编译器检查：开启 `-Wformat -Wformat-security`；
4. 系统级防护：ASLR、栈保护（canary）、RELRO、NX；
5. 代码审计和静态分析，查找不安全的格式化函数调用。

### 四、答题版 🟨

> 格式化字符串攻击是利用程序对格式化函数使用不当的漏洞：当用户可控的数据被直接当作格式串（如 `printf(buf)`）时，攻击者构造 `%x`、`%s`、`%n` 等格式符，使函数按格式符从栈上取参数。由于格式化函数是变参函数，无法判断实际参数个数，格式符多于实际参数时仍会读取栈上其他数据，攻击者可借此读取栈内容、读取任意地址数据，或用 `%n` 向任意地址写入数据，造成信息泄露、程序崩溃，甚至改写返回地址执行任意代码。防御方法是使用固定格式串（`printf("%s", buf)`）、过滤输入、开启编译器警告，并配合 ASLR、canary 等防护。

> 用户输入被当作格式串 → `%x / %s` 读内存，`%n` 写内存。


## 缓冲区溢出攻击

### 一、定义 🟨

**缓冲区溢出（Buffer Overflow）**：程序向缓冲区写入的数据**超过了缓冲区的容量**，多出的数据覆盖了相邻的内存，从而破坏数据、使程序崩溃，甚至让攻击者**劫持程序的控制流**，执行任意代码。

### 二、以栈溢出为例

**1. 栈帧结构**

函数被调用时，栈帧从**高地址到低地址**依次是：参数、返回地址、旧 EBP（帧指针）、局部变量（如 `buf[64]`）。

- 数据写入 `buf` 时，是从低地址向**高地址**填充；
- 写入超过 64 字节，会依次覆盖：旧 EBP → **返回地址**；
- 函数结束执行 `ret` 时，从栈上取出返回地址装入 **EIP**（EIP 存放下一条要执行的指令地址），程序就跳转到该地址继续执行。

**2. 漏洞成因：不检查长度的函数** 🟨

```c
void func(char *input) {
    char buf[64];
    strcpy(buf, input);   // 不检查 input 的长度
}

int main(int argc, char *argv[]) {
    func(argv[1]);        // 用户可控的输入
    return 0;
}
```

- `strcpy` 一直复制到 `\0` 为止，不关心 `buf` 只有 64 字节；
- 若 `input` 长度超过 64，多出的部分就写到 `buf` 之外的高地址，覆盖返回地址。

**3. 栈布局对比**

![格式化字符串攻击栈参数示意图](<./buffer_overflow_stack_normal_vs_attack.svg>)


**4. 攻击过程**

1. 找到不检查长度的输入点（如上面的 `strcpy(buf, input)`）；
2. 构造超长输入，布局（从低地址到高地址）为：

```text
[ NOP Sled ][ Shellcode ][ 重复的目标地址 × N ]
```

   - 重复的目标地址指向 NOP 区；其中恰好有一个落在返回地址的位置，覆盖它；
3. 函数返回时，`ret` 弹出被篡改的返回地址，装入 EIP，程序跳转到 NOP 区；
4. CPU 顺着 NOP 一路"滑"到 Shellcode，执行 `execve("/bin/sh")`，攻击者获得 shell。

**5. 几个关键概念**

| 概念 | 说明 |
| --- | --- |
| EIP | 存放下一条要执行的指令地址；控制了 EIP 就控制了程序 |
| 返回地址 | 函数返回后要执行的位置，保存在栈上，与局部变量相邻，因此可被覆盖 |
| Shellcode | 攻击者注入的机器码，通常用来启动 shell（`execve("/bin/sh")`） |
| NOP Sled（滑雪板） | 大量 `\x90`（空操作指令）。攻击者很难精确知道 shellcode 地址，返回地址只要落在 NOP 区任意位置，就会滑到 shellcode，提高成功率 |
| 重复返回地址 | 不知道返回地址在缓冲区后的精确偏移，就重复写多遍目标地址，保证其中一个覆盖到位 |

### 三、防御

1. **使用安全函数**：`fgets`、`strncpy`、`snprintf` 等，限制写入长度；
2. **栈保护（Canary）**：在返回地址前放一个随机值，函数返回前检查是否被改，被改则终止程序（编译选项 `-fstack-protector`）；
3. **NX / DEP**（数据执行保护）：栈和堆标记为不可执行，注入的 shellcode 无法运行；
4. **ASLR**（地址空间布局随机化）：每次运行栈、堆、库的地址都不同，攻击者猜不到 shellcode 地址；
5. **边界检查与安全语言**：使用带边界检查的语言（如 Java、Rust）；
6. 代码审计、静态分析、模糊测试（Fuzzing），查找不安全的函数调用。

### 四、答题版

> 缓冲区溢出是指程序向缓冲区写入的数据超过其容量，覆盖相邻内存的漏洞。以栈溢出为例：函数的局部变量（如 `buf`）与返回地址在栈上相邻，当程序使用 `gets`、`strcpy` 等不检查长度的函数时，攻击者构造超长输入，在覆盖缓冲区后继续覆盖旧 EBP 和返回地址，并将返回地址改为指向注入的 shellcode（常配合 NOP Sled 提高命中率）。函数返回时，被篡改的返回地址装入 EIP，程序跳转执行 shellcode，攻击者获得控制权。防御方法包括使用安全函数限制长度、栈保护（Canary）、不可执行栈（NX/DEP）、地址随机化（ASLR）以及代码审计。

> 输入超过缓冲区 → 覆盖返回地址 → 劫持 EIP → 执行 shellcode。
