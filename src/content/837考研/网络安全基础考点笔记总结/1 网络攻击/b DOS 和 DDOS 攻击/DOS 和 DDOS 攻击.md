# DoS 和 DDoS 攻击

## 一、基本概念

- **DoS**：拒绝服务攻击（Denial of Service），指攻击者通过消耗目标的资源或利用其漏洞，使目标无法为合法用户提供正常服务。核心是"让服务不可用"。通常由单一设备或攻击者发起，流量来源单一。
- **DDoS**：分布式拒绝服务（Distributed DoS），是 DoS 的分布式版本。攻击者控制大量被入侵的主机（僵尸网络），让它们同时向同一目标发起攻击，流量来源分散。

> DoS / DDoS 只看**攻击源数量**；下面五类看**攻击机制**，两个维度相互独立，同一攻击可同时属于多类。

## 二、分类总览

| 类型 | 分类维度 | 核心思想 | 典型攻击 |
| --- | --- | --- | --- |
| 剧毒型 | 攻击手段 | 利用协议或软件缺陷，少量畸形报文使目标崩溃 | Ping of Death、Teardrop、Land、Chargen 循环 |
| 风暴型 | 攻击手段 | 用海量报文耗尽带宽或资源 | TCP SYN Flood、HTTP CC、IP 欺骗、Ping Flood、Smurf |
| 重定向型 | 攻击效果 | 让流量被引向错误的地方，通信中断或被劫持 | ARP 欺骗（中间人）、DNS 欺骗 |
| 反射型 | 报文路径 | 借第三方反射器间接攻击，并放大流量 | Smurf、DNS / NTP / Chargen / SSDP 放大 |
| 直接型 | 报文路径 | 攻击者（僵尸主机）直接向目标发包 | 僵尸网络 DDoS |

## 三、剧毒型拒绝服务攻击

特点：靠缺陷而不靠流量，一组畸形报文即可使目标崩溃。

### 1. Ping of Death
1. 攻击者把一个超长的 ICMP Echo 请求拆成多个分片发送，最后一个分片的"偏移量 + 数据长度"超过 65535 字节。
2. 每个分片本身都合法（单个 IP 包没有超过 65535），所以途中的路由器和检查都能放行。
3. 目标主机把分片缓存起来，等到全部到齐才重组。重组时才发现总长度超出了预分配的缓冲区，旧实现没有检查长度，导致缓冲区溢出或内存分配错误，TCP/IP 协议栈崩溃。

- 关键限制：IPv4 头部"总长度"字段为 16 位，数据包最大 65535 B（$ 2^{16} - 1 $）。

### 2. Teardrop
1. 同样利用 IP 分片重组的漏洞，通过修改 IP 分片头的**偏移量**字段实现。
2. 发送多个分片：第一个分片偏移量为 0、长度为 N；第二个分片的偏移量小于第一个分片的尾部，造成分片偏移量重叠。
3. 操作系统重组这些重叠分片时发生内存分配错误，系统崩溃。

### 3. Land
1. 构造特殊的 TCP SYN 包，把**源地址和目标地址都设置为受害者的 IP**。
2. 受害者收到后会尝试与自己建立连接："自己与自己通信"（$ SYN → SYN+ACK → ACK $）。
3. 形成大量空连接，耗尽系统连接资源，导致服务不可用。

### 4. Chargen 循环攻击
1. 利用 Chargen（字符生成器）等网络服务，让一个或两个系统的端口**输出成为另一个端口的输入**，形成首尾相连的数据反馈环路。
2. 环路不断产生大量数据，迅速耗尽带宽或系统资源，造成拒绝服务。

## 四、风暴型拒绝服务攻击

特点：发送海量报文，耗尽带宽或系统资源。

### 1. TCP SYN Flood
1. SYN Flood 利用 TCP 三次握手的缺陷：攻击者向目标发送大量 SYN=1 的报文（通常伪造源地址），服务器收到后分配资源、回复 SYN-ACK 并进入半连接状态，等待第三次握手的 ACK。
2. 由于攻击者不回应（伪造的源地址无法响应），半连接一直占用服务器的半连接队列和内存，直到超时。
3. 队列被占满后，服务器无法再接受新的连接请求，合法用户无法建立连接，造成拒绝服务。

### 2. HTTP CC 攻击
- CC 即 Challenge Collapsar，又称代理攻击。
1. 攻击者控制大量**僵尸主机**，通过 HTTP 代理向受害者服务器发送大量**合法的网页请求**。
2. 若请求的是 **CPU 消耗极大**的页面（如复杂逻辑的 PHP、ASP、JSP），大量并发请求会迅速耗尽服务器 CPU，服务瘫痪。
3. 特点：使用合法请求攻击，难以通过简单的防火墙规则拦截。

### 3. IP 欺骗
- 攻击者伪造一台主机的 IP 地址，冒充该主机与目标通信。
- 本质是破坏基于 IP 地址的网络信任关系，常作为其他攻击（如 Smurf）的辅助手段。

### 4. Ping Flood（ICMP 泛洪）
- 利用大量控制主机，向受害者发送海量 ICMP Echo 请求（Ping 包），占满带宽或系统资源，导致正常通信瘫痪。

### 5. Smurf
1. 伪造源地址：攻击者构造 **ICMP Echo** 请求（ping），把源 IP 伪造成受害者的 IP。
2. 发往广播地址：目的地址设为某个网络的广播地址，该网络内所有主机都会收到这个请求。
3. 主机集体应答：网络内每台主机都向"源地址"（也就是受害者）回送 Echo 应答。
4. 受害者被淹没：大量应答涌向受害者，占满带宽并消耗处理资源，造成拒绝服务。

- Smurf 同时是**典型的反射型** DoS 攻击。

> 风暴型的核心是"以量取胜"：SYN Flood 耗连接资源，CC 耗 CPU，Ping Flood / Smurf 耗带宽。

## 五、重定向拒绝服务攻击

特点：让流量走向错误的目的地，造成通信中断或被劫持。

### 1. ARP 欺骗（中间人攻击）
- ARP 的核心功能：在局域网内将目标主机的 IP 地址解析为 MAC 地址，以实现数据链路层通信。（ wangan.online 称其属网络层协议，常规归类为链路层与网络层之间。）
- 共享网络：攻击者获取主机 ROOT 权限并设置网卡**混杂模式**即可窃听；交换网络：主要通过 **ARP 欺骗**实现流量劫持。

**原理**
1. 攻击者伪造 IP 与 MAC 的映射关系（可用 ARP 请求/响应报文），刷新目标主机的 ARP 缓存表，使受害者把报文发往错误的 MAC 地址，从而劫持流量。
2. 若同时修改通信双方的 ARP 缓存，则形成**中间人攻击**，攻击者可嗅探、篡改或丢弃流量。

**ARP 安全缺陷（根本原因）**
- **无状态性**：收到 ARP 应答后无条件更新本地缓存，不验证来源；
- **无认证机制**：攻击者可轻易伪造 ARP 报文。
<!-- 
**Tips**
- root 权限：Linux / 类 Unix 系统中的最高权限，类似 Windows 的 Administrator。
- 混杂模式：需要 `CAP_NET_ADMIN`（通常为 root）；`libpcap` 抓包时会自动开启混杂模式，所以无 root 权限无法抓取他人流量。
- 实现方式：`raw socket` 是常见手段，但只要内核允许打开 `PF_PACKET` 并构造 ARP 报文，无需 `raw socket` 也可实现。
- 中间人攻击的严格定义：必须同时污染双方 ARP 缓存，使流量双向经过攻击者，才能完整截获和篡改；仅污染一方只能单向嗅探。
- 隐蔽性：发送 ARP 应答比广播请求更隐蔽，不产生大量广播流量，也不触发 IP 冲突告警，实际攻击中最常用。 -->

**ARP 缓存特性**
- 缓存存储在 RAM 中，重启或掉电立即清空；
- 默认超时：Windows 约 2 分钟，Linux 约 60 秒；
- ARP 以广播方式工作，解析范围仅限本地网络，所以 ARP 欺骗只作用于**同一广播域 / 本网段**。

### 2. DNS 欺骗

**监听式主机欺骗**
1. 在交换网络环境中，先通过 ARP 欺骗冒充 DNS 服务器，欺骗者作为中间人位于 DNS 服务器和受害者之间，配合 sniffer 软件监听，获取 DNS 查询 ID 和端口号。
2. 抢先构造并发送包含恶意地址的 DNS 应答包；真实应答因晚于伪造包被丢弃。
3. 实现缓存投毒，使受害者把域名解析到恶意地址。

**DNS 服务器污染**
1. 发送大量 DNS 请求包，并伪造 DNS 应答包（若计算的端口号和 ID 正确）。
2. DNS 服务器以错误的域名信息更新缓存，无法提供正确解析。
3. 在缓存周期内，所有访问该域名的客户机都被解析到错误地址。

**根本原因**
- DNS 基于无连接的 UDP，缺乏认证机制，仅通过 **ID 和端口号**验证应答真实性，容易被伪造。

> 重定向型的核心是"篡改映射关系"：ARP 篡改 IP-MAC，DNS 篡改域名-IP，使流量去往攻击者指定的地方。

## 六、反射型拒绝服务攻击（放大攻击）

1. **不需要控制大量僵尸网络**，攻击者利用**反射器**（高性能服务器或多个服务器）间接向目标发送大量数据包。
2. 反射节点无法识别发起源是否恶意。
3. 攻击者选用**应答数据远大于请求包**的应用层协议（如 DNS、NTP、Chargen、SSDP），实现流量放大，耗尽目标资源。

- 典型：Smurf、DNS 放大、NTP 放大、Chargen 放大。
- 前提：伪造源地址为受害者 IP（IP 欺骗）。
> DNS 放大攻击属于反射型拒绝服务攻击。DNS 基于 UDP，服务器收到查询报文后不验证源地址的真实性，直接把响应发往报文中的源地址。攻击者把查询报文的源地址伪造成受害主机的 IP，发给大量 DNS 服务器（反射器），并选择响应远大于请求的查询类型（如 ANY、TXT）。于是大量大尺寸响应报文涌向受害主机，占满其带宽和资源，实现流量放大和拒绝服务。

> 反射型的核心是"借刀杀人 + 放大"：请求小、应答大，应答被送往伪造的源地址（受害者）。

## 七、直接型拒绝服务攻击（僵尸网络 DDoS）

- 攻击者（通过僵尸网络）直接向目标发起攻击，不经过反射器。

**僵尸网络类型**
- **IRC 僵尸网络**：僵尸主人通过 IRC 协议，利用 IRC 服务器的**域名**（而非固定 IP）连接受控主机上的僵尸程序，可通过蜜罐蜜网捕捉 IRC 服务器。
- **P2P 僵尸网络**：基于公开的 P2P 协议，采用分布式、对等结构。

**直接型 vs 反射型**
| | 直接型 | 反射型 |
| --- | --- | --- |
| 发包者 | 僵尸主机主动发起攻击 | 反射器被动应答 |
| 是否需要僵尸网络 | 需要 | 不需要 |
| 流量放大 | 取决于僵尸数量 | 依靠应答大于请求的协议 |

> 直接型的核心是"人海战术"：僵尸主机自己就是攻击者，而不是反射器。
