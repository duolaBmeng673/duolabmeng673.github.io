# 各层网络协议缺陷及攻击

## 一、应用层

### DNS（域名系统）⭐

**基本作用/功能**
- 实现域名与 IP 地址的相互解析，采用"请求-响应"方式，基于 **UDP**。
- DNS 服务器在 TTL 有效期内用缓存直接响应用户查询。

**脆弱性来源**
- **协议脆弱性**：
  - 基于 UDP，无连接，源地址可伪造；
  - 查询与响应之间无认证，仅靠 2 字节的**事务 ID**（0~65535）匹配，易被猜测；
  - 缓存机制：虚假记录一旦写入缓存，在 TTL 内持续生效并扩散；
  - 缺乏反污染机制；
  - 响应报文尺寸远大于请求报文尺寸。
- **实现脆弱性**：DNS 软件在实现层面的漏洞与缺陷（如 BIND 缓冲区溢出、解析处理错误）。
- **操作脆弱性**：人为配置或管理错误（如域名配置错误、域名管理不当）。

**攻击方式**
1. **事务 ID 欺骗**：伪装成 DNS 服务器，提前向 client 发送与查询数据报 ID 相同的响应数据报，进行 DNS 欺骗。实现方法：网络监听（如 ARP 欺骗），或猜测 ID（2 字节，0~65535）。
2. **缓存中毒**：DNS server 在 TTL 内用 cache 响应用户查询，attacker 诱骗其缓存大 TTL 数值的虚假域名记录，实现欺骗和扩散。特点：隐蔽性强、间接攻击、缓存难检测。
3. **网络通信攻击**（特性：响应报文尺寸 >> 请求报文尺寸）：
   - **DoS 攻击**：发送大量 DNS 查询报文，对 server 造成 DoS 攻击；同时利用 DNS "请求-响应"的依赖关系，阻断客户端与服务器之间的通信链路。
   - **DNS 域名解析过程劫持**：劫持解析路径，并伪装成指定的 DNS 应答（如伪装成 Google DNS 8.8.8.8，客户端的查询被转到攻击者的解析器 1.2.3.4，由它返回伪造结果）。

## 二、传输层

### TCP ⭐

**基本作用/功能**
- 面向连接、可靠的字节流传输协议，通过**三次握手**建立连接：
  1. 客户端发送 SYN（Seq = X）；
  2. 服务器回复 SYN-ACK（Seq = Y，Ack = X+1）；
  3. 客户端发送 ACK（Seq = X+1，Ack = Y+1）。

**脆弱性来源**
- 握手未完成时服务器就要为半连接分配资源，而资源有限（半连接队列）；
- 以序列号/确认号作为报文合法性的主要依据，序号可被猜测或嗅探；
- 无加密、无认证，且继承 IP 源地址可伪造的缺陷。

**攻击方式**
1. **网络扫描**：连接状态可被探测，用于识别开放的端口和服务，包括 SYN 扫描、ACK 扫描、FIN 扫描、全连接扫描。
2. **拒绝服务（DoS）**：
   - **SYN Flood**：发送大量伪造源地址的 SYN 请求，服务器回复 SYN-ACK 后一直等待第三次握手，半连接占满资源，正常用户无法建立连接；
   - **连接耗尽**：占满服务器的连接资源。
3. **会话劫持（TCP Session Hijacking）**：利用序列号伪造合法数据包，接管连接。

   | 类型 | 能否看到流量 | 攻击条件 | 效果 |
   | --- | --- | --- | --- |
   | 旁路劫持（Blind Hijacking） | 不可见 | 必须猜测 IP、端口、Seq、Ack，伪造报文并预测序列号 | 向连接中注入数据，可能接管连接，成功率较低 |
   | 非旁路劫持（Non-blind Hijacking） | 可见（可嗅探） | 可直接获取当前 Seq/Ack | 基于抓包构造合法报文，更容易成功，直接接管会话 |
4. **RST 注入**：伪造 RST 报文强行中断连接，对长连接（如 BGP 会话）影响尤其大。


## 三、网络层

### IPv4 

**基本作用/功能**
- 网络层核心协议，无连接、尽力而为地转发数据报，提供逻辑寻址。

**脆弱性来源**
- 无状态、无认证、无加密（也无抗重放机制）；
- 不验证源地址，路由器无数据追踪功能，无法确认数据来源是否真实；
- 无带宽控制，带宽与系统资源有限，易被耗尽；
- IP 地址数量匮乏。

**攻击方式**
- **假冒 & 篡改**：IP 欺骗，伪造源地址，修改数据内容；
- **监听 & 侦察**：明文传输，数据可被窃听，用于网络探测；
- **DDoS**：源地址可伪造且无带宽控制，难以追溯与限制；
- **分片攻击**：利用分片重组缺陷，如 Teardrop、Ping of Death。

### IPv6

**基本作用/功能**
- 128 位地址，解决地址匮乏；支持地址自动配置（SLAAC），用邻居发现协议（NDP）取代 ARP；可结合 IPsec 使用（提供认证与加密）。
- **IPv4 → IPv6 过渡方法**：双协议栈、隧道、网络地址转换（协议翻译，如 NAT64/DNS64）。

**脆弱性来源**
- **过渡机制风险**：双栈使攻击面叠加；隧道的内层流量可绕过防火墙检测；不同协议栈安全策略不一致；
- **NDP/ICMPv6 缺乏认证**：路由通告（RA）、邻居请求（NS）、邻居通告（NA）报文都可伪造，SLAAC 默认信任 RA；
- **编址机制**：接口标识可由 MAC 生成（EUI-64），暴露设备信息，易被追踪；
- **PKI 体系**：IPsec / SEND 依赖证书和 CA，体系复杂，CA 或私钥一旦被攻破则信任崩溃；
- **协议依赖风险**：IPv6 依赖 ICMPv6 完成 NDP 和路径 MTU 发现，不能简单地全部过滤。

**攻击方式**
- **伪造 RA**：伪装成路由器，使主机把攻击者当作默认网关 → 修改默认网关 → 中间人攻击（MITM）；
- **伪造 NA（针对 DAD）**：主机用 DAD 检测地址冲突，攻击者伪造 NA 谎称地址已被占用，使节点无法完成地址自动配置 → 拒绝服务（DoS）；
- **伪造前缀通告**：发布错误前缀，导致错误的地址配置和路由，网络中断或流量异常；
- **邻居欺骗**（类似 ARP 欺骗）、邻居缓存投毒；
- **隧道/过渡机制攻击**：利用隧道隐藏攻击流量，绕过边界检测，扩大攻击面。

### ICMP ⭐

**基本作用/功能**
- **ICMP**：在主机与路由器之间传递控制消息和差错报告（目的不可达、回送请求/应答、重定向、超时等）。
**脆弱性来源**
- 控制消息无认证，可被伪造；
- 对广播地址的回送请求会引起多主机应答，具有放大效应。

**攻击方式**
- **拒绝服务**：利用"目的不可达、Echo 回送请求/应答"等消息发起 DoS，如 **Ping Flood**、**Smurf 攻击**（伪造受害者为源地址，向广播地址发 Echo 请求，大量主机的应答涌向受害者）；
- **目的不可达攻击**：发送大量伪造的 ICMP Unreachable 消息，使目标认为目的主机或网络不可达，导致通信中断、性能下降；
- **路由破坏**：利用"改变路由（重定向）"机制篡改主机路由表，实现流量劫持；
- **隐蔽通信**：木马程序利用 ICMP 报文隐蔽传递数据；
- **网络扫描**：用 Echo 请求探测存活主机。

### 路由协议

> 按功能归入网络层。严格按承载方式：RIP 基于 UDP、BGP 基于 TCP，教材中属应用层协议；OSPF 直接封装在 IP 数据报中（协议号 89），属网络层协议。

#### RIP

**基本作用/功能**
- 距离向量内部网关协议，**基于 UDP**。
- 请求报文：发现其他使用 RIP 的路由器；更新报文：分发路由表。

**脆弱性来源**
- **RIPv1 不支持认证**，路由器无条件信任邻居发来的更新报文；
- 基于 UDP，源地址可伪造。

**攻击方式**
- 伪造 RIP 更新报文，**任意污染附近路由器的路由表** → 路由欺骗、流量劫持或黑洞。

**防范**
- 只允许接收 RIP 报文、禁止发送；
- 配置访问控制列表，只 permit 特定源 IP 的 RIP 报文进入路由表；
- （补充）使用支持认证的 RIPv2。

#### OSPF ⭐

**基本作用/功能**
- 链路状态内部网关协议，用**洪泛法**向自治系统内所有路由器发送与本路由器**相邻的所有路由器的链路状态**；
- 只有链路状态发生变化时才用洪泛法更新，收敛快；
- 直接封装在 IP 数据报中传送。

**脆弱性来源**
- 路由器默认信任收到的链路状态通告（LSA），认证薄弱或未启用；
- 洪泛机制使伪造的 LSA 会被快速传播到全网；
- LSA 的老化（max age）和序号机制可被利用来触发网络更新。

**攻击方式**
- **LSA 最大年龄攻击**：LSA 的 max age = 1 小时，到期视为过期并被删除。攻击者截获正常 LSA，将其年龄伪造成 max age 再发出 → 全网路由器删除该 LSA → 原路由器收到洪泛回来的、以自己为通告路由器的 LSA，发现不是自己的当前版本，于是重新生成序号更大的 LSA 洪泛 → 攻击者再次伪造 → 反复洪泛和 SPF 重算，网络混乱 & DoS。
- **LSA 最大序号攻击**：LSA 序号最大值为 0x7FFFFFFF，不能再增加。攻击者发送序号为最大值、通告路由器为受害者的伪造 LSA → 全网接受 → 受害路由器收到这条以自己为通告路由器的 LSA，序号已经到顶，没法再用"序号加一"生成更新的版本，只能先把它清除（置为 max age 洪泛），再从初始序号重新生成 → 攻击者不断重复，网络不稳定。
- **序号加一攻击**：LSA 平时不会频繁变化（拓扑变化或定时刷新时才重新生成并将序号加一）。攻击者伪造一条与正版同一通告路由器、**序号比正版大 1、内容被篡改**的 LSA，路由器因其序号更新而用它替换正版 → 基于错误拓扑计算路由。原路由器会重新生成更大序号的正版来纠正，所以效果可能短暂。
- **重放攻击**：重放旧报文时可将其**更改成更高序列号**，使路由器把它当作新报文接受。

  | 攻击类型 | 作用对象 | 攻击机制 | 安全影响 |
  | --- | --- | --- | --- |
  | Hello 报文重放（邻居列表型） | 邻居关系 | 重放不包含自己的 Hello 报文，使对方认为链路不可双向通信 | 邻居状态变为 Init，无法建立邻接关系 |
  | Hello 报文重放（超时/序列型） | 邻居存活机制 | 重放"旧或异常 Hello"，干扰 Hello 新鲜度判断，或导致合法 Hello 被忽略 | 超过 RouterDeadInterval 后邻居失效，邻接关系中断 |
  | LSA 报文重放 | 拓扑数据库（LSDB） | 重放旧 LSA 或伪造高序列号 LSA，引发洪泛传播 | 触发反复 SPF（最短路径优先）计算，路由震荡，CPU 消耗增加，可能 DoS |
- **篡改攻击**：修改报文内容后重新发送。

#### BGP

**基本作用/功能**
- 应用于 **AS 与 AS 之间**的边界路由器，且一般该路由器为**骨干路由器**（Router）；
- BGP 会话：不同 BGP Router 之间建立的 **TCP 连接**。

**脆弱性来源**
- **缺乏安全可信的路由认证机制**，无法对路由信息进行安全验证（security verify）：
  - 一个 AS 通告不属于自己的前缀时，也被其他 BGP 路由器认为合法，并接受、传播；
- **使用 TCP**，继承 TCP 的安全问题。

**攻击方式**
- **数字大炮（BGP 震荡）**：频繁制造路由可达/不可达的变化，引发全网路由震荡。
- **BGP 劫持**：攻击者通过伪造或篡改 BGP 路由更新信息，使 Internet 把发往目标地的流量错误地发给攻击者的网络。

## 四、数据链路层

### ARP（地址解析协议）⭐

> 介于链路层与网络层之间，通常归入链路层。

**基本作用/功能**
- 把 IP 地址解析为 MAC 地址：IP 用于跨网络寻址，而同一局域网内实际发帧需要对方的 MAC 地址。
- 每台主机维护一张 **ARP 表（缓存）**，保存"IP → MAC"的对应关系。
- 工作流程：
  1. **确定要解析的 IP**：目的主机与本机在同一子网，则解析**目的主机**的 MAC；不在同一子网，则解析**默认网关**的 MAC（数据先交给网关转发）；
  2. **查 ARP 表**：有对应表项，直接用该 MAC 封装帧发送；
  3. **广播 ARP 请求**：没有表项时，在局域网内广播"谁是该 IP？请告诉我你的 MAC"；
  4. **单播 ARP 应答**：IP 匹配的主机回复自己的 MAC，其他主机忽略该请求；
  5. **更新 ARP 表**：请求者收到应答，把（IP-MAC）对存入 ARP 表，再发送数据；
  6. **表项老化**：ARP 表项有生存期，超时即删除，之后需重新解析。

**脆弱性来源**
- **无认证**，主机无条件信任收到的 ARP 报文；
- **无状态**：即使没有发过请求，收到应答也会更新缓存；
- 采用广播，缓存表项可被随意覆盖。

**攻击方式**
1. **ARP 欺骗**：攻击者 C 向 A 发送$（IP_B, MAC_C）$，向 B 发送$（IP_A, MAC_C）$，使 A、B 的 ARP 表中对方的 MAC 都变成 C 的 MAC。
   - 攻击者可截获 A 与 B 之间的数据包；
   - 若将截获的 data 转发给应接收的主机 → **中间人窃听/篡改**；
   - 若不转发 → 断网（DoS）；
   - 冒充网关 → 劫持整个局域网的出口流量。
2. **端口盗用（交换网络监听）**：交换机根据源 MAC 学习 MAC 地址表。攻击者 C 发送**源 MAC 为受害者 A 的 MAC** 的帧，使交换机把 A 的 MAC 映射到 C 所在的端口（**MAC 表被污染**）。此后发给 A 的数据会被交换机转发到 C 的端口，由 C 接收；C 再按需转发给 A，实现监听。
3. **MAC 泛洪**：不断发送大量伪造源 MAC 的帧，把交换机学习表填满。表满后，交换机学不到新的 MAC，而合法主机的表项会因老化被挤掉，之后发往这些主机的帧在表里查不到目的 MAC，就会被泛洪到所有端口，攻击者所在的端口也能收到，从而实现嗅探。
