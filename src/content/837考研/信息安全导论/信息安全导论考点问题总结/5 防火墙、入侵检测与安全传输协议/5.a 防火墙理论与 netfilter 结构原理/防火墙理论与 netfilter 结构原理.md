# 防火墙理论与 netfilter 结构原理

## 防火墙概念 / 什么是防火墙？
- 防火墙指的是一个由**软件和硬件设备**组合而成、在**内部网络和外部网络之间**构造的安全保护屏障，从而**保护内部网络免受外部非法用户**的侵人。
- 简单地说，防火墙是位于两个或多个网络之间，执行**访问控制策略**的一个或一组系统，是一类防范措施的总称。

## 从应用对象上和存在形式上，防火墙可以怎么分类？
- **从应用对象上来看：** 可以分为**企业防火墙**和**个人防火墙**两大类，企业防火墙的主要作用是保护整个企业网络免受外部网络的攻击，而个人防火墙则是保护个人计算机系统的安全。
- **从存在形式上来看：** 可以分为**硬件防火墙**和**软件防火墻**，硬件防火墻由于采用特殊的硬件设备，从而具有较高的性能，一般可以作为独立的设备部署在网络中，企业防火墙多数是硬件防火墻；而软件防火墙则是一套需要安装在某台计算机系统上来执行防护任务的安全软件，个人防火墙都是软件防火墙。

## 防火墙作为网络安全设备的主要作用？
1. 网络流量过滤
2. 网络监控审计
3. 支持 NAT 部署
4. 支持 DMZ
5. 支持 VPN
                                
## （原题）描述主机防火墙应用与独立防火墙在功能、部署方式方面的区别。
- 主机防火墙通：软件防火墙，独立防火墙：硬件防火墙        

**（1）功能方面：** 主机防火墙主要保护单台主机，可针对具体主机及应用程序控制进出流量；独立防火墙主要保护网络或多个主机，提供网络边界访问控制和流量过滤等功能。

**（2）部署方式方面：** 主机防火墙通常以软件形式安装在主机上；独立防火墙通常以独立的硬件设备形式部署在网络边界或关键位置。

## 从技术特征上来看，防火墙可以怎么分类？
依据防火墙的技术特征，常见的防火墙可以分为**包过滤防火墙、代理防火墙和个人防火墙**。

## 包过滤防火墙的安全策略和工作层？
- **安全策略：** 根据数据包头的源地址、目的地址，端口号和协议类型等标志来制定安全策略
- **工作层：** 其主要工作在**网络层和传输层。**

## 什么是 ACL？讲述一下动态包过滤和静态包过滤？
1. **ACL**      
一系列允许和拒绝匹配规则的集合，利用这些规则来告诉防火墙哪些数据包允许通过，哪些数据包被拒绝。
2. **静态包过滤**
- 静态包过滤是指防火墙根据定义好的包过滤规则审查每个数据包，以便确定其是否与某一条包过滤规则匹配。          
（过滤规则基于数据包的包头信息进行制定，并存储在ACL 中。包头信息中包括IP 源地址、IP 目标地址、传输协议（TCP、UDP、ICMP 等）、TCP/UDP目标端口、ICMP消息类型等。）
3. **动态包过滤**
- 动态包过滤是指防火墻采用动态配置包过滤规则的方法。
- 根据需求动态地添加或删除 ACL 中的过滤规则，并通过对其批准建立的每一个连接进行跟踪，更加灵活地实现对网络连接访问的控制。

## NAT 技术全称？静态 NAT 和动态 NAT 区别？NAT 作用？
- NAT 技术全称：**网络地址翻译**（Network Address Translation,NAT）
- 静态NAT：**一对一映射**私有IP转换到真实IP
- 动态NAT：当内部私有IP 地址访问外网时，NAT 系统**随机**从 IP 地址缓冲池中**取出一个真实的 IP 地址**为这次访问进行地址翻译。
- NAT 作用：缓解IP地址不足、隐藏内部主机ip、过滤ip地址、流量均衡

## Netfilter 与 IPTables 工作层次以及其作用？

- Netfilter：处于**内核层**，是内核的一部分，由一些信息包过滤表组成，这些表包含内核用来控制信息包过滤的规则集。
- Iptables：位于**用户层**，是一种管理包过滤规则的工具，可以完成插入、修改和删除包过滤规则的操作。

## Netfilter / IPtable 是如何工作的？
1. **Netfilter 是内核层的数据包处理框架**，嵌入在 Linux **内核层 IP 协议栈**中，负责提供数据包处理机制并实际执行处理，包括：
   * **表、链、规则的层次结构**：Netfilter 是表的容器，表是链的容器，链是规则的容器。规则存储在内核的表中。主要有三个功能表：
     * Filter：包过滤，决定放行或丢弃数据包，含 INPUT（目的地址是本机）、FORWARD（目的地址不是本机，需转发）、OUTPUT（本机产生）三条链；
     * NAT：网络地址转换；
     * Mangle：修改数据包字段值，用于流量控制和服务质量。
   * **设置钩子点（Hook）**：在协议栈关键位置设置五个钩子点：
     * IP_PRE_ROUTING：数据包从数据链路层进入网络层；
     * IP_LOCAL_IN：数据包从网络层进入传输层；
     * IP_FORWARD：数据包在网络层转发；
     * IP_POST_ROUTING：数据包从网络层进入数据链路层；
     * IP_LOCAL_OUT：数据包从传输层进入网络层。
   * **注册钩子函数**：每个钩子允许注册若干钩子函数，系统按优先级形成钩子函数指针链，数据包到达钩子点时被依次提交处理。Filter 只在 IP_LOCAL_IN、IP_FORWARD、IP_LOCAL_OUT 三点注册钩子函数，每个钩子函数对应一张包过滤表，并依据表中规则检查数据包。
   * **执行数据包处理**：钩子函数依据规则对数据包进行过滤、地址转换、字段修改等操作。

2. **IPtables 是用户空间的规则管理工具**，本身不存储规则，也不执行数据包处理，只负责通过命令对内核中 Netfilter 的表、链、规则进行增删改查（名字由此而来）。命令格式：

   > IPtables 命令 = 工作表 + 使用链 + 规则操作 + 目标动作 + 匹配条件

   * 工作表：指定操作哪张表，缺省为 filter；
   * 使用链：指定表下的某条链，即确定钩子点；
   * 规则操作：添加、插入、删除、替换、列出规则；
   * 目标动作：ACCEPT（继续传递）或 DROP（丢弃）；
   * 匹配条件：用于匹配包头信息的特征，如地址、端口等。

3. **规则匹配方式**：链上的规则按优先级形成规则队列，顺序匹配。某条规则匹配成功，就执行其目标动作并结束匹配；否则转向下一条；全部匹配失败，则执行该链的默认策略。

4. **两者关系**：Netfilter 在内核空间提供机制并执行，IPtables 在用户空间提供配置接口，二者配合构成 Linux 防火墙。流程为：管理员运行 IPtables 命令 → 规则写入内核中 Netfilter 的对应表和链 → 数据包经过钩子点时，钩子函数查表匹配并执行动作。


> **一句话记忆**：Netfilter 是内核里的“规则库和执行者”，IPtables 是用户手里的“规则编辑器”。
