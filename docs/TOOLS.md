# 工具栏目与空教室查询

## 架构与入口

博客继续采用 Astro 7 静态构建。工具是独立栏目，不作为技术／学习笔记发布：

- `/tools/`：索引，只有实际实现的工具卡片。
- `/tools/classrooms/`：哈工大空教室查询。
- `src/data/tools.ts`：统一工具注册表。添加工具页面和注册记录即可扩展索引及 sitemap，不需要给每项工具增加顶栏链接。
- `src/components/ToolCard.astro` 与 `src/styles/tools/index.css`：工具卡片和栏目布局，使用全站主题变量。
- 顶栏只增加“工具”，首页在近期笔记之后增加简短入口，不改变文章、搜索和 RSS 的数据范围。

## 原项目与复用边界

来源为站点作者的 `duolaBmeng673/hit-classroom-select`，本轮优先检查本地源码，版本 `42256c0`。原项目为无第三方依赖的 Node.js 22 本机服务、原生 JavaScript 前端和 Shadow DOM 界面，没有前端框架或独立前端路由。

`public/vendor/hit-classroom/room-app.js` 是原 `work/room-app.js` 的逐字节副本，包含完整的校验、查询参数、学校数据解析、筛选、缓存、收藏及离线导出逻辑。来源和 SHA-256 记录在同目录 README 中。没有复制登录页面、本机后台、认证脚本、诊断记录、真实快照或凭据。原项目文件不移动、不覆盖。

Astro 页面直接挂载现有 `mount({ enhanced: false })`，使用原组件已有的 Shadow DOM，没有 iframe、React 或新 npm 依赖。公开博客的主机不是学校主机，也未开启本机后台模式，因此不会向学校发起查询请求，更不会自动探测 localhost。没有添加跨域代理或后端。

## 部署后实际能力

GitHub Pages 可运行：

- 原格式完整 JSON 快照的导入和校验；不存在默认、随机或模拟教室数据。
- 星期、起始大节、连续空闲大节数、教室搜索和收藏筛选。
- 原有 24 条初始展示和“显示全部结果”，不把部分展示误作完整数据。
- 原有三态语义：未排课／占用／未知。未知状态不判为空闲，占用仍有暖橙圆点与文字标识。
- 缓存、采集时间和过期提示；适配层记住已验证快照的查询条件，让刷新恢复对应缓存。
- 导出原格式 JSON 和独立离线 HTML；导出保留原采集时间，不伪装为最新结果。

GitHub Pages **不能**替代本机服务完成学校登录与实时查询。学期、教学周、校区、楼宇四项在线选择及人工二次认证保留在原本机助手；博客展示当前导入快照的学期、周次、校区和楼宇，不生成虚假的在线选项。换条件时在原助手查询并导出相应快照，再导入博客。

本机启动方式：在原项目目录执行 `npm start`，然后打开 `http://127.0.0.1:8766/`。需要 Mac、Node.js 22+、有权访问的学校账号和可访问学校系统的校园网络。博客页的说明与链接引导用户自行打开本机助手，登录只发生在本机页面。该地址只属于当前设备，手机不能借此访问另一台电脑。

学校认证使用 HTTPS，但原教务查询接口使用 HTTP；未改变接口或绕过学校认证、校园网限制。不建议把本机服务发布到公网，也没有为此配置 CORS。若未来必须在博客内直接实时查询，需要另行设计经授权的服务或客户端桥接，不能仅靠 GitHub Pages 静态页面实现。

## 主题与样式

`src/scripts/tools/classrooms.ts` 只适配展示：将原组件样式中的颜色映射到博客 `--bg`、`--surface`、`--text`、`--accent`、`--warm` 等变量，再附加 `src/styles/tools/classrooms.css` 的局部规则。

变量通过 Shadow DOM 原生继承，博客切换浅色、深色或跟随系统时，组件立即跟随，无需另存主题或跨 iframe 通信。查询交互用青绿色，纸色背景、中性边框和字体与博客统一；暖陶色只作占用／提示等语义强调。占用保留“占”及圆点，未知保留“待核”和虚线，不能只靠颜色判断。

隐藏原独立应用的重复页头与宣传标题，保留博客导航、工具页 H1、快照位置和所有离线控件。圆角、焦点、按钮及输入框沿用主题规则；移动端单列，星期按钮和六大节状态完整显示。导航在 1080px 以下为搜索预留独立行，600px 以下将导航另排一行，避免压缩搜索和主题控件。

独立 HTML 导出沿用原项目的自包含样式，便于脱离博客使用；不自动继承博客主题。内嵌工具页的主题同步与独立导出的外观是不同范围。

## 数据与维护

导入和缓存均在浏览器本地处理，不上传。只导入原助手导出的公共教室占用 JSON，不导入账号、Cookie、CAS Ticket 或认证日志。缓存与收藏由原引擎维护；本站不跟踪使用情况、不生成活动热力图记录。

更新上游时，先检查实际源码和差异，再替换经过审查的单个核心文件，更新来源版本与校验值并执行测试。不要复制整个原项目的本地目录，尤其不要复制采集结果、导出、截图和认证材料。
